# /qa:add — 出题

用户出题意图：

$ARGUMENTS

严格按以下流程执行（不要跳步）：

1. **转写上下文**（必须先做）：从当前会话提炼与本题相关的关键事实——用户的决策与要求原话、已确认的契约（接口形状、格式、词汇表、边界行为）、相关文件与行号。写成紧凑摘要，作为出题依据交给子代理。摘要要忠实，不要替用户"补全"未说定的内容。
2. **初始化题库**：`bash .qa-bank/bin/quiz.sh init`（幂等）。
3. **spawn 出题子代理**：调用 Agent 工具，subagent_type 为 `qa-writer`（若可选列表显示带插件前缀如 `self-quiz:qa-writer`，则用带前缀名称）。prompt 必须包含：
   - 用户的出题意图（上方原文完整转交）；
   - 你转写的上下文摘要；
   - 要求其按 qa-writer 规范成对写 questions/ 与 answers/ 文件，并返回新题 ID 与概括。
4. 子代理返回后向用户报告：新题 ID、题型（T1-T7）、偏差类型（A-E）、题面内容。若子代理标注了"待确认"冲突，原样转述给用户请其裁决。

注意：主代理知道题目与答案是正常且必要的（你是出题协作方）；但此后**不要主动复述答案内容**，避免污染后续自检的真实性。
